# 2026-10-23：經實際 DOM 驗證的 Oyez 案例引用

上一輪已能從官方 API 取出兩所大學，但原始評估的來源清單只有 Oyez 前端頁等網址，沒有 API 網址。這輪先用原始起點跑三個失敗案例：球隊答案正確，來源仍是 API，所以嚴格 joint 為 0/3。沒有修改標準答案或把 API 證據直接改名成前端證據。

實際檢查發現，先以官方 API 讀取案例後，瀏覽器可以使用同一個 guarded Fetcher 的快取，讓 Oyez 的原本 JavaScript 正常呈現案例事實。[公開前端實測](../benchmarks/oyez-render-20261023-probe.json)取得的 DOM 包含兩所大學、案名及事實內容；實際前端來源為 `https://www.oyez.org/cases/1966/37`。

## 行為

只對已驗證身分的 Oyez 案例，且瀏覽器已啟用、剩餘時間大於 8.5 秒時，嘗試原本的前端網址。瀏覽器仍受既有 6 秒、20 個請求及 6 MB 上限約束，沒有增加總題目時間或開放 POST。最壞情況保留約 2.5 秒給後續模型讀取與驗證。

前端引用必須是瀏覽器真正回傳的 Page，並符合官方主機、相同 term/docket、案名及所有可用的主要案例文字段落。主要段落涵蓋 facts、question、conclusion，也檢查其子標題內容；只顯示標題、metadata、一小部分事實、其他案例、截斷或錯誤頁，都不足以替換 API 來源。

通過驗證後，從真正的 DOM 擷取答案並引用該前端網址。API 中未出現在 DOM 的描述與結構欄位仍保留為 API 證據，例如 docket number。瀏覽器停用、時間不足或前端驗證失敗時，仍使用已驗證的 API 證據。沒有更動 API URL 的來源標籤。

使用的仍是免費、無需帳號的官方端點，沒有第三方服務、API key、信用卡或計費設定。

## 同來源、同模型比較

[凍結九題](../benchmarks/case-citation-20261023-cases.json)包含真實球隊、消息來源、API 專屬 docket number、直接 API 入口、錯案名、空殼頁、瀏覽器停用、不完整前端及時間保留控制。使用真實擷取的 HTML、JavaScript、API 回應，經本地實際 HTTP 與新的 Chromium 重播；沒有在比較中接觸公網。

修改前為 `587ca65`，前後共用同一個完整 Qwen3-4B BF16 模型、1536-token 上限，交替執行。[最終比較](../benchmarks/case-citation-20261023-final.json)：**7/9 → 9/9，2 個改善、0 個退步**；所有原本正確結果保留。模型呼叫同為 18 次，平均 2.107 → 2.774 秒，這是來源正確性的改善，沒有宣稱加速。執行中程式雜湊未變動。

14 個直接來源與內容檢查全部通過，包括子標題下缺少事實段落的拒絕案例。另有[固定語意回覆的 HTTP 控制](../benchmarks/case-citation-20261023-controls-final.json)通過 9/9；它只證明流程，不作為模型準確率。保留第一輪模型比較、早期控制及各自凍結檔，沒有覆寫。

## 原始搜尋流程

最終模型服務也執行了同一組原始三題：相同起始網址、相同問題、相同 frozen gold、相同 24 秒與深度 2 設定，使用實際公開 HTTP、搜尋及瀏覽器。題目 SHA 與本輪修改前的三題實測相同，三份 HTTP capture 雜湊都驗證通過，無遺漏。[驗證紀錄](../benchmarks/case-citation-20261023-live-validation.json)

| 原始題目 | 結果 |
|---|---|
| `simpleqa-395`，1963 年誹謗案的兩個球隊 | `University of Georgia and University of Alabama`，引用 `https://www.oyez.org/cases/1966/37`，答案與原始來源都正確 |
| `simpleqa-37`，1985 年的配偶姓名 | 選定來源缺少所需年份見證，維持棄答 |
| `simpleqa-32`，RIAA 金唱片認證日期 | RIAA 原始頁 403，可讀公告不足以提供該認證日期，維持棄答 |

球隊題從原本的 Wikipedia 起點出發，實際搜尋發現 Oyez 後才讀取官方 API、呈現前端、選取雙名稱及獨立驗證。最終耗時 12.616 秒；瀏覽器 18 個請求、636,609 bytes、2.388 秒，`content_matched=true`。

這組已公開的三題，精確答案為 **1/3 → 1/3**，嚴格答案加來源為 **0/3 → 1/3**。公開網路回應會變動，因此此實測不作為因果或速度證明；固定九題比較提供獨立的修改效果證據。

## 回歸與限制

一般 CPU 讀取 15/15、P0 16/16、Oyez 身分與內容 24/24 及 HTTP 整合 4/4、多片段協定 28/28 加 12 個來源/計畫控制均保留。六個原有實際 Chromium 整合檢查另存新檔，包括重新導向、延遲回應、無窮 JavaScript、全新 CLI worker 及私有目的地阻擋；沒有覆寫舊 browser-validation 紀錄。

最新完整十二題實測仍是答案 4/12、joint 2/12；不能把三題子集的改善拼成新十二題分數。本輪沒有新 holdout、全量重跑、映像重建、推送或競賽提交，AMD 執行也仍未驗證。任務自有模型在驗證後結束，沒有變動其他使用者程序。

# 2026-10-23：官方 Oyez 來源與有數量限制的多片段答案

原本的擷取協定要求答案是來源中的一段連續文字。真實失敗題問兩個球隊，Oyez 事實段落分別寫出 University of Georgia 和 University of Alabama，中間夾著教練姓名；模型即使認出兩所大學，也會因合成字串不連續而被拒絕。Oyez 前端另外只回傳 JavaScript 外殼，原本流程看不到案例事實。

現在對發現的 Oyez 案例網址讀取官方 `api.oyez.org` 公開端點。使用者已明確允許此不需註冊的免費入口；沒有使用 Oanor、第三方包裝、API key、信用卡或計費方案。不把未公布限額解讀為無限使用，HTTP 請求仍受原有逾時、大小、快取與有限重試約束。

案例來源必須同時符合請求的 term、docket、回應最終網址、JSON `href` 及有效案例名稱；錯案、非官方主機、不完整回應和限流錯誤都不提供答案證據。只整理指定案例內容欄位，重用既有 HTML 隱藏內容與腳本過濾，保留結構與 JSON 欄位定位。單段最多 1000 字元，最多 96 個段落。這份真實回應由通用 JSON 解析的 786 個段落整理為 11 個可讀段落。

明確問 two/three/four 或 2–4 個成員的文字問題，可回傳同一段來源的逐字 `answers` 陣列。程式驗證數量、每個片段、重複、重疊及輸出長度後，以固定連接詞組成答案；每個成員仍各自通過來源、表格、方向與事件年份檢查，再以獨立模型判斷整個答案是否符合問題。這不是任意摘要或跨來源合成；成員別名是否指同一實體仍依賴語意驗證。

## 固定資料與本地完整 4B 模型

[固定 12 題](../benchmarks/case-members-20261023-cases.json) 包含真實 Oyez 案例、API 網址入口、錯案資料、兩隊及教練、只有一隊、不同得獎年份、同年雙人、一般單值、三國、同隊別名及連續雙名稱。API 與前端回應以原始擷取 SHA 驗證；其餘是明確標記的人工控制資料。

修改前使用 `4141065`，修改後使用目前程式；在同一個 Qwen3-4B BF16 模型與同一份來源資料上交替執行，輸入上限 1536 tokens，單題 12 秒、深度 0。兩個引擎共用目前模型後端，僅新請求的明確成員限制啟用新提示與陣列協定；一般單值提示不變。

[第一輪](../benchmarks/case-members-20261023-paired.json)及[更換提示範例後第二輪](../benchmarks/case-members-20261023-paired-v2.json)均為 **6/12 → 12/12，6 個改善、0 個退步**。第二輪將提示範例名稱與所有測試答案分離，並將空陣列明確棄答轉成正常無證據狀態。最後修正計畫中的 `cardinality` 與要求的成員數一致；最終比較見[第三輪](../benchmarks/case-members-20261023-paired-v3.json)。每輪使用相同題目與來源位元組，各自保留凍結的程式雜湊，沒有覆寫前兩輪。

最終第三輪同樣是 **6/12 → 12/12，6 個改善、0 個退步**，所有原本正確結果都保留，執行中程式未變動。真實隊名題現在回傳 `University of Georgia and University of Alabama`，兩個逐字片段及同一段事實都保留在診斷中。日期不同的雙人名單被逐成員年份檢查拒絕，錯案資料在模型前就被拒絕。

最終平均單題時間 1.171 → 1.183 秒，模型呼叫 16 → 19；沒有宣稱加速。每輪使用者原有的其他 GPU 程序都未變動，任務自有模型在比較後結束；最後檢查 GPU 為 871 MiB，該輪 PID 已不存在。

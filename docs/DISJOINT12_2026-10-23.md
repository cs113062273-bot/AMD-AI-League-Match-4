# 2026-10-23：新版首次不重疊外網評估

本輪在 c659785 的 production 程式上，從先前未選取的 780 筆 SimpleQA Verified 資料均勻抽出 12 題，seed 940220。排除先前 20+100+100 題，沒有按網站、主題、難度或答案篩選。使用同一份已保存的上游 CSV；原始問題、答案、來源與既定日期／整數別名均未修改。

執行前凍結題目、程式雜湊與評估條件：本機完整 Qwen3-4B BF16、context cap 1536、budget 24 秒、max_depth 2、實際搜尋與選擇性瀏覽器。從第一個上游 supporting URL 開始；這是有起始來源的檢索評估，不是官方 SimpleQA 或 Match 4 評分。

|---|---:|

| 回傳來源符合凍結來源集合 | 3/12 |

來源規則預先要求至少一個來源，且每個回傳 URL 都在凍結來源集合；這比舊通用 runner 的「任一來源符合」更嚴格。不能直接把本輪比例與舊 100 題比例相減當成改善幅度。樣本也太小，不能推論整體正確率。

兩題答案符合、來源不同：Bard subclass 與 Basie Reunion 演奏者。三題有回答但字串不符合：橋長的 `390 m` 對上游完整範圍描述、Goldsboro 河流答錯，以及第一行歌詞請求回傳了過長節錄。保留全部失分，不事後增補別名，也不把這三題一概當成格式問題。

平均每題 9.378 秒，合計 37 次模型呼叫，10 次請求發生 context pruning。程式前後雜湊相同，沒有執行中修改。12 份 HTTP capture 都無容量漏存，各案 SHA 存在完整記錄；capture 不含瀏覽器最終 DOM。自有模型已停止，停止後 GPU 619 MiB。

這批題目在第一次觀察後即視為已暴露資料。後續修正與重跑只能作開發證據，不能繼續稱為未見題。

## 下一輪依據

- 多個 query 的 provider 回應只對上 first、two、day 等問句詞，仍被判成相關而停止備援搜尋，最後浪費頁數在字典網站。相關的模型 hints 被附加在原 query 尾端，未改變這種結果。
- `first and last name` 被誤判為兩欄表格投影，跳過了單一姓名讀取。
- 獨立語意檢查仍接受了錯誤的地理方位關係，證明「model_verified」不等於事實正確。
- 第一行／最短答案的範圍控制仍需改善。

優先用實際保存的回應與受控 HTTP 隔離搜尋問題；保留首輪結果，後續另存報告。

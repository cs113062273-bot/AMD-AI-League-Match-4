# 2026-10-23：完整姓名使用單一姓名讀取

Follow-up: the [projection-field change](PROJECTION_FIELDS_2026-10-23.md) recovered the remaining name-email case in a separate four-case comparison. The seven-case results below retain their original stage.

首次不重疊外網評估的 simpleqa-37 要求 first and last name，卻被規劃成兩個獨立表格欄位；因此即使頁面有完整姓名，也會跳過一般讀取。本次把 first/given 與 last/family/surname 的姓名組合辨識為單一完整姓名。明確欄位／column 請求，以及姓名＋email、日期＋時間等不同輸出，保留 compose_fields。

另以原題預先列出的 Alchetron URL 取得 HTTP 200，頁面有包含完整姓名及婚姻年份的可讀段落。這是提供正確頁面的 reader 測試；先前完整外網流程沒有發現該頁，不能把 reader 恢復說成外網搜尋已解決。

## 相同模型服務比較

在同一個自有完整 Qwen3-4B BF16 服務中，以 3fe17ab 對比修改後。七題、fixture SHA 與 context cap 1536 相同，max_depth 0、budget 12 秒，不搜尋。

| 結果 | 修改前 | 修改後 |
|---|---:|---:|
| 答案與來源精確符合 | 3/7 | 6/7 |
| 三個正向完整姓名案例 | 0/3 | 3/3 |
| 姓氏未記錄／年份不符的棄答 | 2/2 | 2/2 |
| 原有日期＋時間組合 | 1/1 | 1/1 |
| 名字＋email 組合 | 0/1 | 0/1 |

三項恢復、零退步。修改後可讀出原題完整姓名，以及兩個自編文字場景。缺少姓氏、年份不符時仍棄答。名字＋email 仍失敗，原因是 First name 與 Name 欄位被粗略詞彙匹配成歧義，待下一步修正。

前版大量跳過讀取，平均 0.068 秒、僅一次模型呼叫；修正後平均 0.969 秒、11 次呼叫。這是增加有效讀取，沒有速度提升主張。程式執行前後雜湊相同；模型已停止，停止後 GPU 919 MiB。

## 其他驗證與限制

既有 [proof／HTTP 27/27](../benchmarks/fullname-20261023-proofs.json)、[transfer 10/10 與 metamorphic 16/16](../benchmarks/fullname-20261023-transfer.json)、[CPU 15/15](../benchmarks/fullname-20261023-regression.json) 保留，編譯與 whitespace 檢查通過。

此修改允許完整姓名進入既有逐字選擇、來源／型別檢查及獨立語意驗證，沒有憑記憶填姓名，也未新增跨欄拼接姓名的運算。分開欄位且沒有可逐字複製完整姓名的來源仍可能棄答。一般語意驗證也仍可能誤判；本輪已確認先前地理誤答的段落只有「河流在城市附近」，缺少所問方位關係，需另處理。

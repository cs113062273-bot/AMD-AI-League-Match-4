# 保留段落內的明確欄位標籤

這一步只使用 CPU、已保存的網頁與模型輸入的序列化函式。沒有啟動模型、瀏覽器或公開網路請求。

## 實際問題

已曝光的 `simpleqa-3120` 抓取內容中，Soccer Wiki 有一段 `<p><span>Full Name:</span> …</p>`。舊解析器保留了文字，但沒有保留標籤與值的欄位關係。相同三份來源、原始問題與排序下，這個完整姓名段落排在第 11 段；模型實際只收到前 8 段，因此看不到它。前面包含縮寫姓名、國籍、隊伍、身高及出生日期等 JSON-LD 欄位。

新解析器遇到段落開頭以 span、b 或 strong 明確標示、以冒號結尾的短標籤時，另外保留 `field` 段落。證據文字完全沿用來源，原本的普通段落也保留。沒有把一般加粗文字或任意冒號句子推定成欄位。

欄位名稱最多 80 字元、6 個詞，值最多 350 字元；空標籤、空值、不是段落開頭、換行或包含另一個明確標籤的段落不新增欄位。隱藏內容沿用原有移除流程。

## CPU 驗證與限制

[同一批 19 個檢查](../benchmarks/inline-fields-20261023.json)由 11/19 變成 **19/19**，8 個改善、0 個退步。包括標籤與值、值內行內格式、隱藏文字、非標籤的加粗、過長資料、同段多欄及原始 HTTP capture。

相同原始內容的完整姓名段落從 **第 11 段提升到第 4 段**，實際序列化的前 8 段也包含該欄位。capture SHA256 已核對，沒有修改答案清單或加入人名特例。

這是證據可見性的改善，**不是模型答對率**。該姓名段落仍缺少題目所需的本地出生年份佐證，既有驗證器仍拒絕其候選答案；沒有放寬年份、來源或獨立語意驗證。後續要解決的問題，是如何從同一份文件的可靠結構保留人物資料範圍，而非把旁邊任意年份移入證據。

既有 CPU 檢查保持通過：[代表性解析 15/15](../benchmarks/inline-fields-20261023-reader-regression.json)、[年份約束 41/41](../benchmarks/inline-fields-20261023-year-regression.json)、[首行結構 22/22](../benchmarks/inline-fields-20261023-line-regression.json)、[組合證據 27/27](../benchmarks/inline-fields-20261023-proof-regression.json)、[Oyez 控制 24/24 與 HTTP 整合 4/4](../benchmarks/inline-fields-20261023-oyez-regression.json)。

# 2026-10-22–23：第一批核心修正

範圍：修復會污染後續評測的服務生命週期、模型故障備援與套件實體辨識。這不是陌生題準確率或官方競賽成績。10 月 21 日的 670 題紀錄均保留，不能拿那些舊程式成績當本次修正版的表現。

## 已實作

- 所有模型讀取、驗證、搜尋提示共用 client，傳遞 request ID、絕對到期時間；逾時、連線失敗或上層取消時，另發有界 cancel。服務只允許一個推論工作，不排積壓佇列。
- 服務在打包、傳輸和生成邊界檢查 deadline/cancel，生成使用 stopping criteria；取消或耗盡預算的部分輸出不能被當作答案。推論鎖在送 HTTP 回覆前釋放。過期請求不啟動推論，取消只能匹配相同 request ID。
- health 增加目前工作、busy 次數、最近 32 次生成的輸入/輸出 token、打包/傳輸/生成時間、prefill 加第一個 token 的時間，以及 Torch allocated/reserved 記憶體。此第一 token 指標不是純 prefill；Torch 計數也不是 Windows 共享顯存。
- engine 分開語意無證據、證據拒絕、服務不可用、協定錯誤與預算耗盡。設定使用模型時，一般網頁候選必須有成功的語意讀取及驗證；503、逾時、壞回覆、未讀取，不再自動升格成規則 verified。服務出錯後跳過可選的模型導航/提示，仍能做 CPU/I/O 導航。
- 經驗證的 registry 欄位、精確函式參數綁定與既有日期版本表路徑仍可獨立回答。PyPI/npm 的直接欄位路徑限明確欄位，不以全文關鍵詞分數代替關係證明。
- PyPI 套件名解析不再把「of the PyPI package X」中的 PyPI 當 X；npm 同樣收集明確套件名稱。PyPI 正規化名稱、npm 名稱必須與 API 回覆 identity 相符；PyPI 指定 release 亦核對回覆版本。404 或 identity 不符停止權威直達，不再改查另一個套件。

固定案例使用實際 Engine、parser、HTTP model client。模型回覆由故障服務控制，registry 在 fetch 邊界重播，沒有把標準答案交給 production。基準透過 `git show 81d7a9e` 載入舊 engine/selector/resolver，其他依賴未改，無複製 repo 或模型。

具體前後變化：

- 模型 503、invalid JSON、逾時時，舊版把 JSON-LD 的 `author:false` 回成人名；新版答案及來源均留白，並保留不同失敗原因。
- 問不存在的 `zzqx-nonexistent-pkg-4821`，舊版抓 `/pypi/PyPI/json` 回 2.1；新版只查指定套件，404 後留白。
- 問 httpx 版本，舊版同樣誤查 PyPI；固定回應中新版正確回 0.28.1。這是固定歷史 evidence，不是宣稱它是今日最新版。
- API 回覆屬於另一套件時，新版拒絕；合法授權與參數預設值照常通過。模擬正常模型讀取也可回答，驗證服務失敗則不放行。
- 生產 HTTP handler 的可控工作取消後約 6ms 釋放，client task 取消約 10ms；100ms deadline 後能處理下一題。這些是可控 CPU worker 的觀察，**不是 4B/GPU 取消延遲保證**。
- 真正 `Runtime.infer` 搭配本機 tokenizer、隨機初始化的微型 CPU Qwen3，成功在第一個 token 取消，下一次 generation 正常完成；隨機模型輸出的壞 JSON 明確列為協定錯誤，沒有冒充答對。

## 尚未證明與下一步

最初其他工作占約 6GB GPU，先做 CPU/HTTP 診斷；降至約 1.6GB 後才追加上述完整 4B 短輸入驗證，沒有關閉使用者程式。未重跑 670 題、未下載模型、未重掃權重 SHA、未重建映像。現有 release/image 仍是舊版。

取消屬 cooperative：正在執行的 GPU kernel/prefill 不能由 Python 在中途強制終止，須等下一個檢查點。短輸入已驗證，尚需在顯存有餘裕時，實測原本 context 長度的取消、下一題恢復與峰值記憶體，才能確認上次長輸入連鎖 busy/共享顯存問題改善多少。

模型失敗時限制一般候選作答會降低覆蓋率；這次只證明錯誤放行被堵住、合法直達被保留，沒有宣稱廣域正確率提高。CPU-only 明確停用模型的舊規則路徑仍保留，不能視為通用語意驗證。

下一批先固定正確 evidence，處理主體、關係、時間、表格欄位與 metadata 資格，量出 oracle reader 上限，再決定是否改模型。需要同時報錯→對、對→錯、coverage 與延遲；一般網頁的合法替代來源/格式評分另行裁定，不修改舊 gold。

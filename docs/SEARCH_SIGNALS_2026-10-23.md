# 2026-10-23：搜尋排名的查詢回聲與解題工具頁

先比較了短查詢是否應加上使用者指定的年份。四份實際公開 Lite 搜尋回應顯示，`bernard comrie spouse 1985` 帶回書籍、搜尋頁及轉貼問句的解題頁，沒有帶回已驗證的帶日期傳記。因此沒有採用加年份的提案；`concise_query` 的 AST 與 `5629aaf` 相同。[提案與擷取檢查](../benchmarks/query-years-20261023-proposal-review.json)

這個調查另外找到兩個可重現的候選排序問題，現在已修正。

第一，`q`、`query`、`SE` 等查詢參數中的文字原本也會增加主題相關性。例如 `query=render_mode` 可以讓沒有相關標題或路徑的頁面通過技術欄位搜尋的錨點檢查。現在這些參數只在排名文字中略過；讀取、回傳與簽名網址完全保留，`id`、`package` 等資源識別參數也保留。搜尋排序及一般連結導覽共用此規則。

這不是所有編碼方式都會觸發的錯誤：原始政府網站例子的 `%20` 查詢值在舊程式中原本就排在最後。控制檢查使用確實能在舊版重現誤判的技術識別字及連字號詞組，沒有宣稱該政府網站原本排名很高。

第二，非填字遊戲問題的自動搜尋及連結導覽，略過已觀察到的 Wordplays `/crossword-solver/` 查詢路徑。[網站本身的說明](https://www.wordplays.com/crossword-solver/cheat-sheet)將這類頁面描述為依線索搜尋候選答案的工具；本輪搜尋回應中有直接把整題問題當線索的結果。明確詢問 crossword、clue 或 puzzle 的問題仍可使用該工具，其他文章路徑及外觀相似的不同主機也不受這個規則影響。這是針對一個已確認路徑的規則，不是完整的垃圾網站分類器。

## 驗證

[最終本地 HTTP 比較](../benchmarks/search-signals-20261023-controls-v2.json)使用同一份控制輸出、修改前 `5629aaf` 及目前程式：**3/9 → 9/9，6 個改善、0 個退步**。涵蓋只有查詢文字的假相關頁、編碼參數名稱、技術欄位回聲、真正結果優先、真實 fallback、解題工具隔離，以及填字遊戲、資源 ID 和真實相關標題的保留。

另有 12 個 URL 與導覽控制全部通過，驗證簽名／實際擷取網址保持原樣、身分參數保留、主機與路徑邊界，以及導覽時真實主題連結能排在查詢回聲前。第一稿中 `id=Boreal+Instruments` 在舊版原本也不能形成兩個獨立詞的錨點，因此把正控制改為原本就能辨識的 `id=Boreal-Instruments`；第一稿失敗結果保留，最終比較以 v2 為準。

相同的四份公開 HTML 再經本地實際 HTTP 重播：不加年份的姓名查詢維持原有八個候選與完整順序；另外三份各移除一個解題查詢頁，補進下一個候選。球隊查詢補進 Vanderbilt 展覽頁或報紙文章；加年份姓名查詢補進的仍是一個商品庫存搜尋頁，所以不能把補位視為已經找回答案。

既有控制保留：discovery 7/7、queue 6/6、搜尋錨點 6/6、搜尋批次 3/3、短查詢 9/9、一般 CPU 讀取 15/15、proof 27/27、P0 16/16。沒有修改模型提示、答案驗證規則、請求數或題目時間上限。

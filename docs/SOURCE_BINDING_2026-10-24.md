# 驗證器使用實際選定的來源紀錄

已修正同文字、同欄名跨年份時，驗證器取第一筆來源而拒絕正確選答的問題。
完整本機 HTTP 重現中，選答選到 `Awards 2024` 的 `Winner: Elm Choir`，
舊版卻拿 `Awards 2023` 檢查，回傳 `model_evidence_rejected`；修正後走完
`/select` 與 `/verify`，回傳正確答案及實際來源。這是自製控制案例，不是新題成績。

`agent/evidence_binding.py` 統一機械驗證與語意驗證前的來源解析：
來源 URL、證據、指定位置、欄名、章節及已提供的型別／欄位值／限定資訊必須一致。
指定位置錯誤時不退回同文字的其他紀錄。多成員答案也使用相同來源定位。
年份、欄位、表格及獨立語意驗證均保留；語意端拒絕時仍拒答。

舊呼叫者未提供位置時，先找完整欄名與章節匹配，再容許唯一來源補齊缺少的資訊。
空欄名可以識別整個表格列，不能與同文字的具名儲存格混淆。
不同位置／限定資訊仍有歧義時拒絕；同頁完全相同的重複紀錄可接受。
驗證使用實際來源章節，不能藉由空章節繞過年份限制。
語意請求的證據排序也包含章節，保留所有原始上下文，不刪除衝突資料。

必要的 CPU 修正與回歸到此固定，不擴充網站適配器或其他選配功能。

列明後續實測條件；它不是已執行的模型評測，也沒有抽取或查看新題。
